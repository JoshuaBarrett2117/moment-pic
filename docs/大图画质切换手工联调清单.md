# 大图画质切换手工联调清单

日期：2026-04-20  
执行者：Codex

## 1. 联调目标

本清单用于验证以下能力是否符合预期：

1. 大图查看器支持页内切换 `省流 / 均衡 / 高清 / 原图`。
2. 切换后当前图片会立即重新请求正确的资源。
3. 同一浏览会话内会记住用户上次选择的画质。
4. `高清 / 原图` 档位会自动收敛相邻图片预加载。
5. 设置页默认画质只在没有会话记忆时生效。

## 2. 联调前准备

建议准备至少两类图集：

1. 普通文件夹图集，包含 3 到 5 张分辨率较高的图片。
2. 压缩包图集，包含 3 到 5 张图片。

建议至少准备一张超大图，方便观察不同档位下的加载差异。

## 3. 启动方式

在项目根目录执行：

```powershell
npm run dev:server
```

前端单独启动：

```powershell
npm run dev --workspace @moment-pic/web
```

## 4. 核心检查项

### 4.1 查看器入口

1. 打开任意相册详情页。
2. 点击一张图片进入大图查看器。
3. 确认底部工具条中存在“画质”入口按钮。

预期：

1. 能正常进入查看器。
2. 工具条中可见画质按钮。

### 4.2 画质面板展示

1. 点击“画质”按钮。
2. 观察弹出的选项面板。

预期：

1. 面板正常弹出。
2. 至少包含 `省流 / 均衡 / 高清 / 原图` 四档。
3. 当前选中档位有明显高亮。

### 4.3 当前图即时切换

1. 在同一张图片上，依次切换 `省流 -> 均衡 -> 高清 -> 原图`。
2. 观察图片加载状态和清晰度变化。

预期：

1. 每次切换都会重新进入加载态。
2. 图片切换完成后能正常显示。
3. 不会出现永久白屏或 broken image。
4. 原图档位仍可正常显示。

### 4.4 当前索引不丢失

1. 切到相册中的第 2 张或第 3 张图。
2. 在该图片上切换不同画质。

预期：

1. 切换画质后仍停留在当前这张图。
2. 不会跳回第一张。

### 4.5 会话内记忆

1. 在查看器内把画质切到 `高清` 或 `原图`。
2. 关闭查看器。
3. 重新打开同一相册中的任意图片。

预期：

1. 查看器再次打开时，应沿用上次选择的档位。
2. 不应恢复为设置页默认值。

### 4.6 默认值回退

1. 打开设置页，修改“大图默认画质”。
2. 清空当前标签页的 `sessionStorage`，或新开一个标签页进入应用。
3. 打开大图查看器。

预期：

1. 在没有会话记忆时，查看器应使用设置页中的默认档位。

### 4.7 切图延续当前档位

1. 在查看器中选择 `高清`。
2. 使用左右按钮或滑动切到下一张。

预期：

1. 下一张图继续沿用 `高清`。
2. 计数器上的画质标签保持一致。

### 4.8 高档位预加载收敛

1. 选择 `均衡`，切换几张图，观察切图流畅性。
2. 选择 `高清`，再切换几张图。
3. 选择 `原图`，再切换几张图。

预期：

1. `高清` 档位会显示“减少相邻预加载”的提示。
2. `原图` 档位会显示“关闭相邻预加载”的提示。
3. `原图` 下不应因为预加载而出现明显额外等待放大。

### 4.9 压缩包图集兼容性

1. 打开压缩包图集中的任意图片。
2. 重复执行 `省流 / 均衡 / 高清 / 原图` 切换。

预期：

1. 各档位都能正常显示。
2. 不会因为压缩包来源导致切换失败。

## 5. 可选网络面板检查

如果要更细地确认链路，可以打开浏览器开发者工具的 Network：

1. `省流 / 均衡 / 高清` 应请求 `/api/v1/assets/:assetId/preview?preset=...`
2. `原图` 应请求 `/api/v1/assets/:assetId/original`

预期：

1. 预览档位不应错误命中 `/original`。
2. 原图档位不应错误命中 `/preview`。

## 6. 异常现象记录建议

如果发现问题，建议至少记录：

1. 图集类型：文件夹或压缩包。
2. 当前档位。
3. 当前图片序号。
4. 是否首次打开。
5. 是否刚从其他档位切换过来。
6. Network 中实际请求的 URL。

## 7. 通过标准

满足以下条件即可判定本轮联调通过：

1. 四档画质都能正常显示。
2. 页内切换稳定。
3. 会话记忆生效。
4. 默认值回退正确。
5. 高档位预加载策略符合预期。
6. 文件夹图集与压缩包图集都可正常工作。
