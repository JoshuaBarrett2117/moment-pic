# 第一阶段开发任务拆解

日期：2026-04-09
执行者：Codex

## 1. 阶段目标

第一阶段目标是交付一个可运行的 Web 图库系统，满足以下核心能力：

1. 通过 Docker 部署运行
2. 服务端扫描挂载的图库目录
3. 支持目录图集和 ZIP 图集两种来源
4. 首页展示图集列表
5. 图集详情页展示缩略图列表
6. 点击图片进入大图查看模式
7. 支持上一张、下一张切换

## 2. 第一阶段范围边界

### 2.1 本阶段包含

1. 单个图库根目录挂载与配置
2. 目录图集识别
3. ZIP 根目录图集识别
4. 图集索引建立
5. 缩略图生成与缓存
6. 图集列表页
7. 图集详情页
8. 图片查看器
9. 基础错误处理

### 2.2 本阶段不包含

1. 多用户系统
2. 收藏与标签
3. 自动定时扫描
4. 图集搜索
5. 高级筛选与排序
6. EXIF 展示
7. RAR / 7Z 支持
8. 嵌套 ZIP 支持

## 3. 交付物

第一阶段建议明确交付以下内容：

1. 可运行的前端项目
2. 可运行的后端项目
3. Dockerfile
4. docker-compose.yml
5. 数据库初始化方案
6. 图库扫描与索引能力
7. 缩略图缓存能力
8. 最小可用界面
9. 基础测试
10. 部署说明文档

## 4. 模块拆分

建议拆成 6 个工作模块：

1. 基础工程与部署
2. 图库扫描与统一解构
3. 索引与缓存
4. 后端 API
5. 前端页面与交互
6. 测试与验收

## 5. 开发任务清单

## 5.1 模块 A：基础工程与部署

### A1. 初始化项目结构

任务内容：

1. 创建前端应用
2. 创建后端应用
3. 约定目录结构
4. 统一环境变量方式

建议产物：

1. `apps/web`
2. `apps/server`
3. `docker-compose.yml`
4. `.env.example`

验收标准：

1. 前后端都能本地启动
2. 目录结构清晰
3. 环境变量可被容器读取

### A2. 建立 Docker 部署方案

任务内容：

1. 编写前端 Dockerfile
2. 编写后端 Dockerfile
3. 配置 compose 挂载目录
4. 定义端口、数据库、缓存目录

建议挂载：

1. `/data/library`
2. `/data/cache`
3. `/data/db`

验收标准：

1. `docker compose up` 后可正常启动
2. 容器内可读取挂载图库目录
3. 缓存和数据库文件可落盘

### A3. 建立基础配置体系

任务内容：

1. 配置图库根目录变量
2. 配置数据库路径变量
3. 配置缓存目录变量
4. 配置日志级别变量

验收标准：

1. 应用不依赖硬编码路径
2. 配置变更后无需改代码即可切换运行环境

## 5.2 模块 B：图库扫描与统一解构

### B1. 定义统一领域模型

任务内容：

1. 定义 `Album`
2. 定义 `Asset`
3. 定义 `AlbumSourceType`
4. 定义统一扫描结果 DTO

重点目标：

1. 前端不感知目录图集和 ZIP 图集的差异
2. 后续扩展 RAR / 7Z 时不推翻模型

验收标准：

1. 目录图集和 ZIP 图集都能映射到同一数据结构
2. 字段满足首页、详情页、查看器需求

### B2. 实现目录图集扫描器

任务内容：

1. 扫描图库根目录
2. 识别子文件夹作为图集
3. 收集图集下图片文件
4. 过滤非图片文件
5. 生成排序结果

验收标准：

1. `/图库/风景1/xxx.jpg` 能识别为图集 `风景1`
2. 图集内图片数量正确
3. 图片顺序稳定

### B3. 实现 ZIP 图集扫描器

任务内容：

1. 扫描图库根目录下 ZIP 文件
2. 读取 ZIP 条目
3. 识别根目录图片文件
4. 过滤目录项和非图片文件
5. 生成图集与图片清单

验收标准：

1. `/图库/风景2.zip` 能识别为图集 `风景2`
2. ZIP 根目录下图片被正确收集
3. 不要求本阶段支持 ZIP 内多层目录规则

### B4. 实现统一图集解析层

任务内容：

1. 统一目录图集和 ZIP 图集输出
2. 提供封面选择逻辑
3. 提供资源访问定位信息
4. 提供后续缩略图生成所需输入

验收标准：

1. 后续索引层不需要再区分具体来源类型
2. 能根据资产信息找到原始图片内容

## 5.3 模块 C：索引与缓存

### C1. 设计数据库表结构

任务内容：

1. 设计 `albums` 表
2. 设计 `assets` 表
3. 设计基础索引
4. 设计更新时间字段

验收标准：

1. 能支持图集列表查询
2. 能支持按图集查询图片列表
3. 能支持增量刷新预留

### C2. 实现首次扫描入库

任务内容：

1. 执行全量扫描
2. 写入图集记录
3. 写入图片记录
4. 为图集建立封面

验收标准：

1. 首次启动后数据库中存在图集和图片记录
2. 图集数量与实际目录一致
3. 图集封面可被查询出来

### C3. 实现缩略图生成服务

任务内容：

1. 根据原图生成统一尺寸缩略图
2. 对目录图片生成缓存文件
3. 对 ZIP 内图片按需读取并生成缓存
4. 建立缓存命名规则

建议策略：

1. 首次请求时懒生成
2. 后续直接命中缓存

验收标准：

1. 同一图片第二次访问不重复生成
2. 缩略图可稳定显示
3. ZIP 图片无需整包解压

### C4. 实现基础缓存失效策略

任务内容：

1. 基于源文件路径生成缓存键
2. 记录修改时间或版本信息
3. 源文件变化后重新生成缩略图

验收标准：

1. 替换图片后缩略图能刷新
2. 缓存目录可长期复用

## 5.4 模块 D：后端 API

### D1. 图集列表接口

任务内容：

1. 返回图集 ID
2. 返回图集名称
3. 返回来源类型
4. 返回封面地址
5. 返回图片数量

验收标准：

1. 首页能完整渲染图集卡片

### D2. 图集详情接口

任务内容：

1. 根据图集 ID 查询图集信息
2. 返回图片列表
3. 返回缩略图地址
4. 返回图片尺寸和名称

验收标准：

1. 图集详情页能展示缩略图网格

### D3. 缩略图访问接口

任务内容：

1. 根据资产 ID 返回缩略图文件
2. 首次访问自动触发缩略图生成
3. 命中缓存时直接返回

验收标准：

1. 缩略图请求稳定
2. 浏览器端可直接渲染

### D4. 原图访问接口

任务内容：

1. 根据资产 ID 返回原图流
2. 对目录图片直接读取
3. 对 ZIP 图片按条目读取

验收标准：

1. 大图查看器可加载原图
2. ZIP 图集图片可正常打开

### D5. 手动重扫接口

任务内容：

1. 提供手动扫描入口
2. 支持重新建立索引
3. 更新图集与图片记录

验收标准：

1. 新增图集后可被重新扫描发现

## 5.5 模块 E：前端页面与交互

### E1. 图库首页

任务内容：

1. 展示图集卡片列表
2. 展示图集封面
3. 展示图集名称和图片数量
4. 提供空状态提示

验收标准：

1. 能看见 `风景1` 和 `风景2` 两个图集

### E2. 图集详情页

任务内容：

1. 展示图集名称
2. 展示缩略图网格
3. 支持图片懒加载
4. 处理加载失败占位

验收标准：

1. 图集中的所有 JPG 能正常预览

### E3. 图片查看器

任务内容：

1. 点击缩略图打开大图层
2. 支持上一张、下一张
3. 支持关闭查看器
4. 显示当前序号和总数

验收标准：

1. 用户可顺畅切换整组图片

### E4. 基础设置与操作入口

任务内容：

1. 提供手动重扫按钮
2. 提供扫描中状态提示
3. 提供异常状态提示

验收标准：

1. 用户知道当前是否已完成扫描
2. 异常时有明确反馈

## 9. 当前建议的最小切片

如果我们希望尽快开工，我建议先做最小切片：

1. 初始化 `web + server + docker compose`
2. 扫描目录图集和 ZIP 图集
3. 建立 `albums/assets` 两张表
4. 实现图集列表接口和图集详情接口
5. 首页和详情页先跑通
6. 最后补大图查看器和缩略图缓存

这样可以最短路径验证最核心的产品链路。

1. 输出数据库表结构和 API 草案
2. 直接初始化项目骨架

如果你想先把设计补完整，我建议先做：

`数据库表结构 + API 设计`
