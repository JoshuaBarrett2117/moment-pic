# 系统相册智能归纳方案

日期：2026-04-28
执行者：Codex

## 1. 背景与目标

当前系统只具备“普通图集”能力：扫描目录或压缩包后，生成 `Album` 与 `Asset`，再通过 `/api/v1/albums` 系列接口对外提供浏览能力。

后续需要新增一层“系统相册”能力，用于把多个普通图集按相似主体自动归纳到统一入口下，但归纳逻辑不能写死具体图集名，必须基于用户自己的内容动态生成，同时支持用户配置归纳规则，并为未来 AI 自动归纳预留配置与执行链路。

本方案目标：

1. 新增“系统相册”二级抽象，不破坏现有普通图集链路。
2. 支持“规则归纳”和“AI归纳”两套引擎同时生效。
3. 允许用户通过配置控制归纳规则、优先级、阈值和 AI 自动应用策略。
4. 为后续人工修正、反馈学习、候选审核预留数据结构。

## 2. 设计原则

1. 现有 `Album`/`Asset` 仍然是底层事实数据，不直接被系统相册替代。
2. 系统相册只聚合 `Album`，第一期不直接聚合 `Asset`。
3. 用户手动规则优先于 AI 自动结果。
4. 低置信度 AI 结果不直接自动生效，只作为候选建议。
5. 扫描与归纳解耦，归纳作为扫描后的独立步骤执行。
6. 规则与 AI 配置均需持久化，不能写死在代码常量中。

## 3. 当前系统接入点

### 3.1 现有数据边界

- Prisma 模型：`apps/server/prisma/schema.prisma`
- 相册查询服务：`apps/server/src/services/album-service.ts`
- 相册路由：`apps/server/src/routes/albums.ts`
- 扫描服务：`apps/server/src/services/library-scanner.ts`
- SQLite 数据访问：`apps/server/src/services/sqlite-store.ts`

### 3.2 建议接入位置

1. 扫描完成后，在 `library-scanner.ts` 的落库完成节点触发 `rebuildSmartAlbums()`。
2. 新建 `smart-album-service.ts`，承接系统相册构建、查询、重建。
3. 新建 `smart-album-rules-service.ts`，承接规则配置和 AI 配置读写。
4. 新建 `routes/smart-albums.ts` 与 `routes/smart-album-rules.ts`。

## 4. 核心能力拆分

### 4.1 普通图集层

职责：

- 目录和压缩包扫描
- 普通图集元数据维护
- 图片资源维护

现有模型：

- `Album`
- `Asset`

### 4.2 系统相册层

职责：

- 统一承载“归纳后的相册入口”
- 聚合多个普通图集
- 记录归纳来源、置信度、命中原因、人工修正结果

### 4.3 归纳引擎层

两套引擎并行运行：

1. 规则归纳引擎
2. AI 自动归纳引擎

两套引擎均输出标准化候选结果，再由“合并决策器”统一裁决。

建议字段：

- `id`
- `name`
- `normalizedKey`
- `coverAssetId`

- `assetCount`
- `sourceSummary`

## 6. 归纳执行流程

## 6.1 扫描后主流程

1. 扫描普通图集并落库。
2. 读取当前范围内的普通图集列表。
3. 执行通用文本归一化。
4. 执行规则归纳引擎，生成规则候选。
5. 执行 AI 归纳引擎，生成 AI 候选。
6. 应用人工反馈覆盖。
7. 合并候选并生成最终系统相册。
8. 更新系统相册主表、成员表与命中记录表。

## 6.2 归一化步骤

建议抽象为 `normalizeAlbumText(input)`，统一供规则和 AI 使用。

清洗项建议包括：

- 大小写归一
- 全角半角归一
- 多空格压缩
- 去除页数，例如 `50P`、`30P1V`
- 去除大小信息，例如 `1.2GB`、`300MB`
- 去除编号，例如 `NO.001`、`VOL.12`
- 去除纯日期，例如 `2024.10.01`
- 去除纯序号前缀
- 中英文括号、连接符统一

## 6.3 规则归纳引擎

执行顺序：

1. 按 `priority DESC` 读取启用规则。
2. 对每个图集按 `scope` 提取待匹配文本。
3. 应用 `normalizeOptions`。
4. 根据 `matchMode` 判断命中。
5. 输出标准候选记录。

候选输出结构建议：

```json
{
  "albumId": "alb_xxx",
  "sourceEngine": "rule",
  "ruleId": "rule_xxx",
  "normalizedKey": "xxx",
  "suggestedSmartAlbumName": "xxx",
  "confidence": 1,
  "matchedScopes": ["albumName"],
  "matchedTokens": ["xxx"],
  "reason": "matched by rule"
}
```

## 6.4 AI 自动归纳引擎

AI 不直接写库，先输出候选。

第一阶段可先做“伪 AI”版本：

- 基于高频词提取
- 别名候选聚类
- 文本相似度聚类

后续接入真实 AI 模型时，保持输出结构不变。

AI 候选结构建议：

```json
{
  "albumId": "alb_xxx",
  "sourceEngine": "ai",
  "normalizedKey": "xxx",
  "suggestedSmartAlbumName": "xxx",
  "confidence": 0.82,
  "matchedScopes": ["albumName", "sourcePath"],
  "matchedTokens": ["xxx", "yyy"],
  "reason": "clustered by semantic similarity"
}
```

## 6.5 合并决策器

优先级建议如下：

1. 人工排除
2. 人工指定归类
3. 规则 `exclude`
4. 规则 `assignSmartAlbum`
5. 规则 `mergeAlias`
6. AI 高置信度自动归类
7. AI 低置信度候选，仅标记待确认

冲突处理规则：

1. 同一图集命中多个系统相册时，优先级高者胜出。
2. 同优先级时取更高 `confidence`。
3. 若依然冲突，则标记 `review_pending`，不自动归入。

## 7. API 设计

## 7.1 系统相册查询接口

### `GET /api/v1/smart-albums`

用途：

- 查询系统相册列表

查询参数建议：

- `page`
- `pageSize`
- `keyword`
- `status`
- `sortBy`
- `sortOrder`

返回项建议：

- `id`
- `name`
- `coverUrl`
- `albumCount`
- `assetCount`
- `status`
- `updatedAt`

### `GET /api/v1/smart-albums/:smartAlbumId`

用途：

- 查询系统相册详情

### `GET /api/v1/smart-albums/:smartAlbumId/albums`

用途：

- 查询系统相册下的普通图集

## 7.2 规则配置接口

### `GET /api/v1/smart-album-rules`

查询规则列表。

### `POST /api/v1/smart-album-rules`

新增规则。

### `PUT /api/v1/smart-album-rules/:ruleId`

更新规则。

### `DELETE /api/v1/smart-album-rules/:ruleId`

删除规则。

### `POST /api/v1/smart-album-rules/:ruleId/test`

用途：

- 预览该规则会命中哪些普通图集

## 7.3 AI 配置接口

### `GET /api/v1/smart-album-ai-config`

查询当前 AI 配置。

### `PUT /api/v1/smart-album-ai-config`

更新 AI 配置。

### `POST /api/v1/smart-albums/rebuild`

手动重建系统相册。

参数建议：

- `libraryRootId`
- `dryRun`
- `engines`
  - `rule`
  - `ai`

## 9. 分期实施建议

## 9.1 第一阶段

目标：

- 只做规则引擎闭环
- 同时预留 AI 配置表与命中来源字段

交付：

1. 新增系统相册相关表
2. 新增规则配置表
3. 扫描后触发 `rebuildSmartAlbums()`
4. 提供系统相册查询接口
5. 提供规则配置 CRUD 接口
6. 提供规则测试接口

## 9.2 第二阶段

目标：

- 启用 AI 候选生成

交付：

1. 高频词聚类版本 AI 引擎
2. AI 配置接口
3. 低置信度候选待确认状态
4. 命中解释和候选审计信息

## 9.3 第三阶段

目标：

- 引入人工反馈闭环

交付：

1. 成员排除
2. 成员移动
3. 合并/拆分系统相册
4. 将人工修正沉淀为规则或别名

## 10. 推荐的首个开发任务

建议下一步直接开发第一阶段最小闭环：

1. Prisma 新增 `smart_albums`、`smart_album_members`、`smart_album_match_records`、`smart_album_rules`、`smart_album_ai_configs`
2. `sqlite-store.ts` 增加对应的读写函数
3. 新建 `smart-album-service.ts`
4. 在 `library-scanner.ts` 扫描完成后调用 `rebuildSmartAlbums()`
5. 新增 `/api/v1/smart-albums` 与 `/api/v1/smart-album-rules` 路由

这样可以先把“规则归纳可配置、AI 位子留好”的主链路完整跑通，再往上叠管理页面和 AI 自动建议。
